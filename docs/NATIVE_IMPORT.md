# Native IMU-WM v1 recordings

`shakewm.native` imports the native `shakebench.imu_wm.v1` version-1 recording layout. It reads an explicit native manifest, a recording directory, or the immediate recording directories under an input directory. It does not import the simulator, read private project source code, start collection, or change the source recordings.

The importer accepts completed attempts only. It verifies every native file checksum before interpreting RGB, continuous IMU chunks, reset prefill, camera contracts and termination metadata. Failed or incomplete attempts are recorded as exclusions. Main and wrist cameras are explicit input choices; one selected view is written to the normalized episode. Model inputs contain RGB and noisy IMU only. Original pose/state, scenario and excitation seed remain audit and split information.

The native 20 Hz RGB acquisition grid is retained. Window construction selects the configured training rate, normally 10 Hz. IMU acquisitions remain at 200 Hz. For the canonical one-sample delivery delay, acquisition `t` is eligible only once its recorded scheduled delivery `t + 0.005` has occurred. Native actual delivery events are checked against the preceding acquisition values. The initial negative-time reset samples must be invalid. A final acquisition whose delivery falls after episode end is retained in the recording but excluded from normalization and model windows.

The current event-based termination contract is validated against the 5 kHz physics tick, regular RGB/IMU grids, reason and terminated/truncated flags. An off-grid terminal image remains audit evidence; it is never snapped onto the next regular frame or used as a fabricated future target. Completed legacy fixed-duration recordings are accepted only when no event termination contract is declared and all expected regular frames and IMU acquisitions are present.

## Freeze splits before constructing windows

`plan-native-splits` assigns whole connected components sharing state ID, physical state fingerprint, or excitation seed. The physical fingerprint uses the authoritative object pose with a normalized, canonical-sign WXYZ quaternion, plus task, initial velocity and grasp-region conditions. It ignores redundant xy/yaw/quaternion descriptions and sampling or pose-class labels. Thus `q` and `-q`, a `2π` yaw relabeling, or a changed state/basis label do not manufacture a new physical state. The full original state is retained separately as audit provenance. Its default distinct-physical-state target is approximately 80/10/10. It records actual physical-state counts, state-ID counts and component membership; indivisible components can prevent those ratios. `heldout_available` is false if distinct held-out physical states cannot be formed. Importing the same state under different scenarios or names does not create held-out evidence.

`import-native` writes the split plan before normalized episodes. An explicit previously written plan must identify the same source manifests and their exact SHA256 values. Counts, strata, component count and held-out availability are recalculated from the actual final assignments before that plan is saved. Normalized manifests also enforce cross-split state IDs, seeds and physical fingerprints. Thus manually relabeling a normalized episode does not bypass the importer’s physical-state isolation. Regenerate plans produced before the canonical physical-identity contract.

Each normalized episode has a content checksum. Feature caches bind to that content. Normalization records the actual checksums of train episodes, and checkpoint provenance binds to the actual episode checksums across the manifest and the feature-source contract. In cache mode that includes the complete cache index and all feature checksums, across every split. Modifying features and updating the cache’s own checksum still invalidates an old checkpoint. In online mode the online teacher contract is bound instead. Changing between online and cached features requires a new run, because the cache stores FP16 features and has a different input contract. Updating sensor values or images invalidates the relevant normalization, cache and resume contracts even if the manifest text was left unchanged. Old normalization files without `train_sources` must be regenerated with `fit-norm`; checkpoints from earlier provenance contracts should start a new run.

The importer writes a new output directory; it never replaces an existing converted dataset. The normalized `.npz` episodes and source files are data artifacts and must remain outside Git.

## Existing-sample CPU evidence

Two authorized existing simulator recordings were imported locally. They contain one shared physical state and one shared excitation seed, with different gamma conditions. Their frozen split is train only. Each lasts 1.1 seconds and contains 23 acquired RGB frames and 220 IMU acquisitions; 219 live samples are delivered before termination. Ten reset-prefill samples per recording are excluded. Train normalization therefore uses 438 live samples.

At the first 10 Hz cutoff, only 19 live IMU samples have arrived. The first eligible short-IMU frame is at 0.2 seconds. These clips yield zero eligible production windows with context 10, and zero V1 windows with the required long history. The importer does not create padded live history to make them eligible.

A diagnostic context of 3 with horizon 6 yields 14 windows, with valid target counts `[14, 12, 10, 8, 6, 4]`. A small mock teacher ran cache extraction, three CPU training steps with a save/resume boundary after step 1, and fixed-origin train-split evaluation. This requires the explicit `--allow-mock-for-contract-test` flag. Reports label `mock_on_real_contract_test=true` and `heldout=false`. The mock run is contract evidence only; it does not test real V-JEPA features or establish model quality. In this diagnostic, the predictor performs worse than copy-last.

The native parser’s unit tests use generated native-format fixtures. They cover delivery and value pairing, invalid reset history, frame-window consistency, delayed samples, off-grid termination, split isolation, deterministic split counts, source mutation and checkpoint data binding. The earlier executed suite passed 34 tests before the final static-review fixes. A later execution task passed four targeted regressions covering equivalent quaternions, stale external plan summaries, a reindexed modified feature cache and raw-data-content checkpoint binding. It also reran the native mock interface successfully. This record does not claim a fresh full-suite run after the fixes. The earlier partial official-encoder CPU check remains failed; the revised diagnostic-writing script was not run against the checkpoint in this execution task. Further testing was canceled at the user’s request.

Aggregate results and the source manifest fingerprints are recorded in `NATIVE_CPU_REPORT.json`. No RGB, IMU arrays, simulator truth, private simulator source, or pretrained weights are committed.
